| --- | --- | --- | --- |

## Secrets Manager

一言で言うと、<strong>機密情報を安全に管理し、自動ローテーションもできる サービス</strong>

機密情報を入れておくところ  
お金は多少かかるが、機密情報自体がそんなに多くないはずなので、選択していれるといいと認識！

> AWS Secrets Manager は、データベース認証情報、アプリケーション認証情報、OAuth トークン、API キー、およびその他のシークレットをライフサイクル全体で管理、取得、ローテーションするのに役立ちます。多くの AWS サービスは、Secrets Manager でシークレットを保存して使用します。

{% linkcard "https://docs.aws.amazon.com/ja_jp/secretsmanager/latest/userguide/intro.html" %}

公式が示しているようにAPIキーやOAuthトークンなどの機密情報をいれる

ローテーション：パスワードやAPIキーそのものを、定期的に別の値に自動で差し替えること  
万が一漏洩しても、次のローテーションでそのパスワードは無効になるため、被害を限定できる。

※ 漏洩後に自動で無効化されるわけではなく、あくまで「定期的に更新される」という仕組みであることに注意。

ローテーションは、AWS Secrets Managerが自動で呼び出すLambdaが行う

{% linkcard "https://docs.aws.amazon.com/secretsmanager/latest/userguide/rotate-secrets_lambda.html" %}

認証情報の保守（ローテーション）を自動で行ってくれる

{% linkcard "https://zenn.dev/fdnsy/articles/133db8440d052f" %}

## SSM

一言で言うと、<strong>設定値・パラメータを保存・管理する サービス（暗号化も可）</strong>

> AWS Systems Manager のツールである Parameter Store は､設定データ管理と機密管理のための安全な階層型ストレージを提供します。パスワード、データベース文字列、Amazon Machine Image (AMI) ID、ライセンスコードなどのデータをパラメータ値として保存することができます。値はプレーンテキストまたは暗号化されたデータとして保存できます。

{% linkcard "https://docs.aws.amazon.com/ja_jp/systems-manager/latest/userguide/what-is-systems-manager.html" %}

魅力は、とにかく安いことだと認識  
安いので、いっぱいSSMにいれることができる  
外部に遷移するためのURLや手動で変更したい値などを保存しておくことができる

{% linkcard "https://docs.aws.amazon.com/ja_jp/systems-manager/latest/userguide/systems-manager-parameter-store.html" %}

> Parameter Store では、String、StringList、SecureString という 3 タイプのパラメータがサポートされています。 String パラメータまたは StringList パラメータに機密データを保存しないでください。機密データを暗号化したままにする場合は、SecureString パラメータタイプのみを使用します。

<strong>SSMにはパラメータの「型」が3種類ある</strong>

```text
  String      → 平文で保存される ⚠️ 機密情報NG
  StringList  → 平文で保存される ⚠️ 機密情報NG
  SecureString → KMSで暗号化して保存される ✅
```

機密性が高い情報を入れる場合は、必ずSecureString型を選ぶ必要がある  
SecureString型のみKMS API呼び出し料金が発生するので、料金が発生する

## KMS(Key Management Service)

一言で言うと、<strong>暗号化キーそのものを管理する サービス</strong>

データの保存目的ではなく、暗号化キーの保存目的に使用する  
調べていたら出てきたので、データを保存できるものかと勘違いしていた

> AWS Key Management Service (AWS KMS) は、データの暗号化と署名に使用されるキーの作成と制御を容易にする AWS マネージドサービスです。

{% linkcard "https://docs.aws.amazon.com/ja_jp/kms/latest/developerguide/overview.html" %}

### 豆知識

<strong>暗号化</strong>：

- 鍵があれば、値を元の値に戻せるAPIキー保存に使う  
  
- 代表例として、AES、RSAがある  

<strong>ハッシュ化</strong>：

- 一度ハッシュ化をかけると元に戻せない・パスワード保存に使う（パスワードを保存する際にハッシュ化して、保存・確認する際は、入力値に同じハッシュ化をしてDBの値と見比べる）
- 代表として、SHA-256、bcryptがある  
  
- bcryptはハッシュ化時にソルト（ランダム値）を付与するため、同じパスワードでも毎回異なるハッシュ値が生成される。  
  
- ソルトはハッシュ値の中に埋め込まれて保存されるため、ログイン時にソルトを取り出して再ハッシュし比較することで認証できる。  
  
- これにより「よく使われるパスワードのハッシュ値を事前に計算した辞書（レインボーテーブル）」による攻撃を防ぐことができる。
