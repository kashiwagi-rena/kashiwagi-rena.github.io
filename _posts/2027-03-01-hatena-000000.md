## マジックバイトとは？

ファイルの先頭に書かれている特定のバイト列のことです。  
拡張子や Content-Typeより信頼のできる情報のため、バリデーションチェックの確認要項にすることが多いです。  
ただし、マジックバイトは偽装できてしまうため、次のような対策を併用することが多いです。

- サイズ上限: 巨大ファイルによるDoSやコスト増を防ぐ  
  
- 実行権限の剥奪: 万一スクリプトが紛れ込んでも、実行させない  

### 代表的なマジックバイト(オフセット付き)

| 形式 | マジックバイト (hex) | オフセット | 備考 |
| --- | --- | --- | --- |
| PNG | `89 50 4E 47 0D 0A 1A 0A` | 0 | |
| JPEG | `FF D8 FF` | 0 | |
| GIF | `47 49 46 38 39 61` (`GIF89a`) | 0 | `GIF87a` もある |
| PDF | `25 50 44 46` (`%PDF`) | 0 | |
| ZIP (docx/xlsx/jar/apk含む) | `50 4B 03 04` | 0 | 中身まで見ないとOffice文書かZIPか区別できない |
| SQLite | `53 51 4C 69 74 65 20 66 6F 72 6D 61 74 20 33 00` | 0 | |
| MP4 | `66 74 79 70` (`ftyp`) | <strong>4</strong> | 先頭4バイトはボックスサイズ |

オフセット：ファイルの先頭から数えて何バイト目の位置かを示す数値。必ずしも、1文字目からマジックバイトがあると限らないこと。

#### マジックバイト検査

ファイルに書かれている特定のバイト列（マジックバイト）を読み取り、そのファイルの種類を判別する仕組み。  
用途として、ファイルフォーマットの判定が挙げられる。(下のURLを参考にしています。)

#### マジックバイト確認の方法

Lambdaをサーバーに使用していたため、Presigned URLを使用して一時保存用のS3アップロードを行った。  
一時保存用S3へのアップロードをトリガーに、バリデーション用のLambdaで検査を行いました。

##### 処理の流れ

1. クライアントがPresigned URLで一時バケットにアップロード
2. Lambdaがアップロードを検知
3. Lambdaがファイルサイズを確認(上限超過なら拒否・ファイルを削除)
4. Lambdaがファイル先頭の数十バイトを取得
5. 拡張子の許可リストとマジックバイトを照合
6. 不一致なら拒否し、一時バケットから削除(画面には汎用メッセージ、詳細はログに記録)
7. 一致すれば本番バケットへコピーし、一時バケットの元ファイルを削除

#### マジックバイト検査を行った際に感じたこと

- 公式配布の画像でも、拡張子と実際の形式が一致しないことがある(例: 拡張子は .jpg だが中身はWebP)。ユーザーが意図せず検査に弾かれる可能性があるため、案内文で許可形式を伝える必要がある。
  
- 画面には汎用的なメッセージ(「このファイル形式はアップロードできません」など)を表示し、「拡張子とマジックバイトが合いません」という詳細な理由はサーバー側のログにのみに記載する。

#### 今回の構成の限界と今後の課題

マジックバイト検査は、ファイル形式の名乗りが正しいかを確認するもので、中身の安全性までは保証しません。先頭だけを偽装し、後ろにスクリプトを埋め込んだファイルは通過する可能性があります。 今後は、画像は本番保存前の再エンコード、動画はMediaConvertなどの利用を検討したいと考えています。
