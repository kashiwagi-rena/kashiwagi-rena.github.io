### コードレビューの指針が欲しいよ〜

> ですが、現実的にはコードレビューでは最初の3つ（可読性、保守性、堅牢性）が自ずと重視されるのかな、と思います。

最近コードレビューする機会があるけど、なんの指針もないので「自分だったら」を基準に確認してました。この記事読みやすいしいい指針となってくれそう！指針がないレビュアーなんて、される側が嫌だと思うので。

```text
・可読性＝人間にとって読みやすいコードになっていること
・保守性＝変更したり、機能追加したりしやすいコードになっていること
・堅牢性＝壊れにくいコード、不具合を起こしにくいコードになっていること
・正しさの確認＝仕様通りに動作し、不具合を起こさないこと
・セキュリティ＝セキュリティ上の脆弱性がないこと
・パフォーマンス＝十分な処理速度が出せること
```

### ブラウザセキュリティって、考えること多くね？

10年前と今ではセキュリティの更新がされている  
10年前のコードを使用しないでください！！！  
 RFC 9155(2021年)で、「MD5のハッシュ化は非推奨」って言われているやんけ！技術は進歩するんだよ！

 セキュリティ面で考えるべきことは、<strong>「それを突破して{{ 嬉しいこと }}はある？」</strong>をまず考える  
そのハッシュ化を突破して、いいことある？  
それを不正アクセスしていいことある？

英語だけど読む際の負荷が少なくていい

```text
Don't use Math.random(). There are extremely few cases where Math.random() is the right answer. Don't use it, unless you've read this entire article, and determined that it's necessary for your case.
 Don't use crypto.getRandomBytes directly. While it's a CSPRNG, it's easy to bias the result when 'transforming' it, such that the output becomes more predictable.
 If you want to generate random tokens or API keys: Use uuid, specifically the uuid.v4() method. Avoid node-uuid - it's not the same package, and doesn't produce reliably secure random values.
 If you want to generate random numbers in a range: Use random-number-csprng.

//  `Math.random()` は使用しないでください。`Math.random()` が適切な答えとなるケースは極めて稀です。この記事をすべて読み、自分のケースで必要であると判断しない限り、使用しないでください。

 `crypto.getRandomBytes` を直接使用しないでください。これはCSPRNG（暗号論的擬似乱数ジェネレーター）ですが、結果を「変換」する際に偏りが生じやすく、出力が予測しやすくなる可能性があります。

 ランダムなトークンやAPIキーを生成したい場合：`uuid`、特に `uuid.v4()` メソッドを使用してください。`node-uuid` は避けてください。これは同じパッケージではなく、信頼性の高い安全なランダム値を生成しません。

 ある範囲内で乱数を生成したい場合：`random-number-csprng` を使用してください。
```

MD5を使用したハッシュ化は「処理が高速でパスワード保存に適さないアルゴリズム」なので、セキュリティ面ではあまり使わない方がいいと認識
