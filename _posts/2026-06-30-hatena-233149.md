自分用のメモ

## 人為的ミスとデプロイ時間、両方を意識したCIづくり

人間は急ぐと本当に忘れるので、忘れることを前提にコード化していく  
仕組みで自分の問題をクリアしていくことは、多分これからの人にもいい効果を与えるはず

また、デプロイ時間は、6〜7分かかりかなり遅い  
Oxcの導入を考え始めたのは時間短縮のため

### 品質コマンド表

ここで 1 つでも失敗するとデプロイされない。

| コマンド | 説明 |
| --- | --- |
| `npm audit --audit-level=high` | high 以上の脆弱性があればビルドを停止 |
| `npm run format:check` | oxfmt によるフォーマット確認 |
| `npm run lint` | ESLint（0 warnings / 0 errors） |
| `npm run typecheck` | 型チェック |
| `npm run test` | vitest によるユニットテスト |

### コマンド使用で気がついたこと・採用理由

`npm audit --audit-level=high`が、かなり良かった。私が認識していない脆弱性を認識できる。エラーで止まって脆弱性を乗っけたままのコードがデプロイできない！

`npm run format:check`：Oxcのフォーマッタ（oxfmt）に変更するだけで、1分ぐらい早くなり、6〜7分→5〜6分になった。ありがとうRust・・・

`npm run lint`：表の通り、リンターは、ESLintのままに一旦している。<s>調べて乗り換えしている時間がなかったからなのだが、</s>Oxlintを動かすと、Vue.jsファイルで確認して欲しい部分（テンプレート部分）が確認されないらしい・・・  
まだこのアプリの開発を続ける予定なので、Oxc完全移行を今後したい

`npm run typecheck`・`npm run test`：定番だが、入れておくと安心なので採用した

### まとめ

この構成はまだ暫定なので、今後Oxc完全移行を含めて変わっていくはず  
デプロイ時間の短縮ももっとできると思うので、改善していく
